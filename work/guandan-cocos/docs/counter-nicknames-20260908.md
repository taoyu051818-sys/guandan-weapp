# 匹配网名与同花顺花色状态（2026-09-08）

## 本轮变更

- 服务端增加 `server/data/bot-nicknames.json`：版本化文件网名库，100 条原创虚构网名，不抓取真实用户身份。小型只读种子库不额外引入数据库服务；机器人账户仍使用现有平台存储。
- 通过机器人身份稳定分配网名，同桌机器人线性探测避重；房间保存 `botDisplayNames`，恢复时复用。平台账户和房间使用同一分配方式。
- 修复 `weapp-ws.js` 的 `ensureLiveMetadata`：此前每次同步都会把已有网名覆盖为“机器人2/3/4”。现在同步沿用网名，内部 `isAI` / `isBot`、签名身份和结算规则不变。
- 自己的同花顺工具条不再因可用花色为空而隐藏，四个不可用花色置灰，点击无效。
- 记牌器的花色使用独立的公开信息推算；展开时即使四个均不可能也保留灰色图标。用户主动折叠、房间规则禁用记牌器仍正常生效。

## 记牌器口径

从双副牌中扣除当前获准查看的手牌及本局全部公开出牌，按实体牌 ID 去重；只读取其他席位剩余张数，不读取其真实牌面。考虑尚未出现的红心级牌作为万能牌，以及本房间是否允许 A2345；其他席位均不足五张时四个花色全部置灰。

亮起表示“根据公开信息仍有可能”，不是某个玩家实际拥有同花顺，也不是概率值。未知牌可能分散在不同玩家手中，因此该结果是保守上界。进入服务端授权的队友视角时，按当前显示的队友手牌扣除已知牌。

## 灰态与视觉检查

UI/UX 检查采用稳定布局：不改变工具条尺寸和锚点。原始黑色图标直接降饱和仍然很黑，因此不可用状态使用统一灰色矢量剪影；可用状态保留原有素材。灰态节点创建一次、复用并随 HUD 销毁，不引入平台字体差异或循环动画。

## 验证与交付边界

- 网名库数量、唯一性、确定性、房间序列化恢复；真实 WebSocket 入桌后双方看到相同网名。
- 平台自动补位账户的持久化显示名与牌桌分配一致。
- 同花顺公开信息推算：零/一/二张万能牌、重复公开记录、A2345 开关、人数剩牌边界、自己与记牌器状态分离。
- HUD 空花色状态保留、由灰恢复可用、点击不可用花色不触发；TypeScript、架构检查和完整项目回归。
- 独立离线预览 `counter-nicknames-20260908/?preview=gray` 为全灰视觉夹具，`?preview=possible` 为自己全灰但记牌器梅花可用的视觉夹具，不连接生产服务。

本轮只修改本地并构建，未上传微信、未部署服务器。网名修改需同时发布服务端代码及 `server/data/bot-nicknames.json`，仅上传小程序不会改变旧服务器覆盖名字的行为。微信真机回归仍需发布测试包后进行。
