## 1. 决策标记

| 标记 | 含义 | 执行方式 |
| --- | --- | --- |
| A | 可直接吸收 | 许可或用户授权明确，质量合格；保留来源、版本、哈希和许可证后导入 |
| B | 可重写吸收 | 功能/流程有价值，但技术栈、架构或许可不适合复制；只按需求和行为重新实现 |
| C | 只作参考 | 对测试或设计有启发，但当前版本收益低、视觉不一致或存在更好的现有实现 |
| D | 拒绝吸收 | 来源不明、含凭据/个人数据、生成物、缓存、重复备份、质量不合格或与项目无关 |

这四类不是按“文件多不多”划分。一个 70,000 行数据库导出可以全部属于 D；一组 100 个短语音频则可能属于 A。

现状（2026-08-05）：匹配桌会持续采集 game/round start、贡还阶段转换（不含牌面）、play/pass、超时或托管自动动作、round-end 和 room-closed。牌局服通过独立 HMAC、每 match 串行上报；失败的队首事件会在一轮有限尝试后继续以有上限、`unref` 的退避原地重试，后序不能越过它。平台严格验证 schema、时间、连续 sequence 和 match-room 绑定，并以 eventId 幂等去重。普通观战密钥只能写公开动作；会终止匹配的 room-closed 必须同时通过观战签名和结算生命周期签名。公开 GET 强制 15—300 秒延迟，事件 DTO 移除内部 eventId、matchId 和六位 roomId；room-closed 会把比赛标记为 aborted、释放重新匹配且不计正常成绩，已正常 finished 后误到的 room-closed 幂等忽略，之后到达的合法正式结算可覆盖异常回收竞态。默认发送队列仍在进程内；配置可选 `GAME_SPECTATOR_OUTBOX_FILE` 后，单实例会在发送前原子落盘、成功后删除并在重启后按 match/sequence 严格续传，room-closed 仍保留双签名。该文件不能由多实例共享，也没有死信队列或自动跳过，无法接受的队首仍会阻塞本 match 并持续有界退避。牌谱由结算绑定，时间线优先使用严格校验的实时公开事件流，旧牌局服才回退结算 `publicTimeline`。Cocos 已把本人牌谱和延迟观战接到同一套公开状态播放器：事件按 sequence 排序去重，可复原四座位最后动作、桌面已出牌、贡还/出牌/结算/异常关桌阶段，并支持播放、暂停、前后步进和五档比例跳转。观战页按3秒周期增量合并公开事件；位于末尾时自动尾随，回看历史时保留当前 sequence 并显示新进展，用户可显式回到最新；离页、销毁或切到后台会使在途请求和定时回调失效，终局延迟尾部完整后自动停止，临时错误保留当前牌桌并按3/6/12秒有界重试。模型只复制公开字段，不保存或推断隐藏手牌。当前仍缺任意拖动条、音效/特效复演、导演视角和精彩切片，因此是可连续观看的第一版播放器，不是完整赛事转播产品。

4. 为固定牌局和效果实验室增加自动截图基线、性能档位对照和真机音频清单；保持正式包编译期关闭。

### P2：不阻塞核心牌局的扩展

1. 好友房首局准备、房主转移、换座、踢人和房间观战席。
2. 陵水主题表情、互动礼物、举报/禁言，以及统一重新设计的授权素材。
3. 精彩牌局切片、分享、赛事观战席与更完整的回放导演视角。

## 9. 上线前必须补的真实验证

- 四台真机或四个独立会话跑完整房间：开始、连续出牌、不要、炸弹、服务端超时、三类托管、断网、恢复、结算、四人准备、贡还和下一局。
