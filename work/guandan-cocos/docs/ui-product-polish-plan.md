# 部署后 UI 与流程收束计划

日期：2026-09-05。状态：待实施方案，不表示本轮已经改完这些页面。本轮使用 ui-ux-pro-max 的加载反馈、错误恢复与操作一致性原则，将重点放在真实状态和明确下一步，而非增加装饰。

## 边界

只保留大厅与牌桌两个主画布，以 874×402 横屏稿验收。设置、规则、商店展示、结算等用统一弹层/抽屉组织，避免每个小按钮进入一套风格不同的独立页面。

保留当前陵水海滨大厅、倾斜牌桌背景及下叠手牌。不恢复已卸载的几何炸弹、横扫光环或电子出牌音。不扩展本轮未接好的赛事运营和商品交易。

## 开发顺序与交付

### 第一批：把主流程做完整

1. 账号状态：加载、成功、失败、重试四态；Web 明示“外观预览，请在微信进入联机”，不为了浏览器测试打开生产开发登录。
2. 大厅右半边以经典场/好友房为主入口；比赛可保留但弱化。左侧单列小工具，开发项汇总到更多，商城保持“展示/开发中”，不伪装可兑换。
3. 匹配：固定字号显示“正在请求/已入队/正在入桌/失败”，以服务端返回驱动；显示四席占位及真实身份，未获数据不伪造排队人数。
4. 保留满 7 秒后服务端补机器人；取消、超时、入桌失败有各自出口，重复点击不能重复请求或创建多个动画。

验收：从冷启动到首局不存在无说明的等待；任何失败都有重试或返回；可玩入口不以“开发中”结束。匹配状态切换不缩字、不跳版。

### 第二批：牌桌空间与交互

1. 左上：返回大厅；下面一行“我方级数 / 对方级数”。队友信息固定上方偏左，队友操作保留上方牌区。
2. 本方出牌区域与手牌区域建立稳定锚点；下叠保留点数/花色，选中抬起不撞操作按钮。提示、出牌、不要动态居中；无可压牌只显示不要。
3. 倒计时独立，按钮出现自然提示轮到自己；不要为“轮到你”再占一块文字区域。
4. 贡还使用阶段标题、参与座位和选牌要求，避免整屏文字；头游/二游用短标签，出完后的座位信息与在玩玩家区分。
5. 单独核对头像、气泡、最后操作、报单、倒计时、手牌、出牌区和顶栏的层级与命中区域。

重叠只警告，不强制互斥。每一对区域输出：交叠宽×高 px、面积 px²、占区域 A 和区域 B 的比例；记录设计坐标与换算后实际屏幕坐标，不能混算。多个交叠的总体占比按并集计算，不能直接相加重复面积。

例如：交叠 120×18=2160 px²，A 为 120×80，B 为 400×120，则占 A 22.5%、B 4.5%。该数值仅作风险线索；如果重叠发生在空白或牌背可接受，遮住点数/花色、级数、计时或按钮文字则必须调整。

验收：初始 27 张、选中、智能理牌、锁组、提示、多次他人出牌、剩 10/1/0 张和最长牌型分别测试。正常叠牌允许重叠，关键字可读、所有可见操作可点才是硬门槛。

### 第三批：结算与局间状态

1. 结算弹层分为胜负标题、四人游次、双方级数变化和操作区，不再用一段拼接长文本。
2. 准备显示四人分别的状态和总人数；等待其他人、本人已准备、取消准备、下一局同步由权威状态驱动。
3. 房间解散和退出按当前状态显示代价及下一步，不用一个“返回”包办所有场景；恢复牌局直接回到正确最终状态。

验收：结算没有遮住仍需点击的按钮；取消准备和同时下一局无双重页面；退出再进不会带回旧文字/动画。

### 第四批：统一美术与小动效

先复用 `commercial-ui-asset-inventory.md` 中允许使用且适合当前背景的资源：一套头像框、主/次按钮、返回/设置/规则/商城图标、身份与游次标签。不要混用白底广告插画、Emoji 和高光金属 UI。

代码负责尺寸、九宫格、状态切换、按下反馈、进度、名单与数字；图片负责底板质感、图标轮廓、身份装饰。背景不重画、文字不烘焙到图片。轻动效统一用于按钮按下、进入弹层、入座和胜负；不额外增加遮牌的全屏大效果。

## 发布门槛

- 每批交付大厅/牌桌同一分辨率的前后对照图，以及重叠警告清单，不用“感觉不挡”代替记录。
- 自动化覆盖匹配状态、单次请求、离页清理、结算/准备状态与关键触摸区域；真机复核以实际视觉和触摸为准。
- Android/iPhone 各一台完成至少一整场：登录、匹配、选牌、提示、不要、托管、贡还、结算、准备、下一局、退出和重连。
- 每批分别构建、发布、回归，避免同时修改规则、输入坐标、手牌布局和全部 UI 后再寻找回归原因。
