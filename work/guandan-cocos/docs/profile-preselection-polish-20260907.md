# 2026-09-07 资料、快捷语与预选牌打磨

## 本轮实现

- 我方与对家出牌中心间距由 107 调整为 99 逻辑单位；保持落桌前缩至 80%，未增加落桌后的第二段缩放。
- 记牌器默认左移；读取微信窗口和原生胶囊位置换算至 Cocos 画布。展开、拖动、旋转重排时也避让胶囊。普通牌桌区域的交叠仍只告警。
- 快捷语增加独立触控遮挡层和四个座位气泡；气泡显示在手牌上方。关闭、切页、重排会清理面板，保留原节流和屏蔽规则。
- 大厅及牌桌自己的头像打开同一个资料弹窗，不退出当前牌桌。支持手动昵称、默认／小鸡头像，以及用户主动点击微信授权按钮。授权只填入草稿，保存后才更新账号。
- 一键理牌优先保留三连对；三带一对优先搭小对子，不自动带入 10、J、Q、K、A、级牌或王对子。限制仅应用于自动分组选择，手动分组、手动出牌和规则识别保持不变。
- 正常打牌阶段允许非本回合单选、取消和滑选自己的手牌。出牌、不要和提示仍检查当前回合；托管、已出完、结算与提交中的短暂等待继续限制操作。
- 同一局、自己的手牌未改变时，其他玩家的服务器更新不再清空预选；自己的出牌／不要、新一局、手牌改变、结算会清理选择。进入锁牌模式时清理普通预选，避免两种选牌状态混用。

## 后端及隐私边界

- 新增兼容小游戏的 `POST /api/v1/profile`，保留原 PATCH。保存后的资料不会在下次微信登录时被默认资料覆盖。
- `GET /api/v1/profile/avatar` 只允许当前已认证账号读取自己的头像，通过既有业务域名返回图片，不让小游戏直接请求新增 CDN 域名。
- 服务端仅允许指定的微信头像 HTTPS 主机、`/mmopen/` 路径和两个包内头像；禁止任意地址、重定向，限制超时、512 KiB 响应和图片签名。
- 微信端使用小游戏 `wx.createUserInfoButton`，不是小程序 WXML 的 chooseAvatar。不会自动弹授权或擅自同意隐私声明。
- 需在微信后台隐私保护指引中正确声明昵称／头像用途，并在真实手机中确认授权可用。此次没有修改后台指引，也没有代用户授权。
- 当前资料回显覆盖自己的大厅和牌桌；其他客户端的座位公开资料同步不在本轮实现范围内。

## 手机验收清单

1. 重新编译／预览新微信包，勿继续测试旧缓存包。
2. 分别在三个其他座位回合点击、取消、滑选；轮到自己时预选保持，出牌需重新通过当前牌型合法性校验。
3. 手持 777＋99、777＋1010、777＋AA，确认仅 99 被自动搭入；手动选择大对子仍能合法出牌。
4. 展开和拖动记牌器，检查不遮住右上原生胶囊；检查自己和对家出的牌仍各自可读。
5. 两台手机互发快捷语；验证气泡座位、节流和屏蔽。
6. 点自己的头像：手动改名、保存、重启登录；授权取消不改变资料，授权成功后仍需点保存。
7. 真机确认微信头像加载；网络错误后可关闭／重试，不覆盖原头像，不自动读取未经同意的资料。
