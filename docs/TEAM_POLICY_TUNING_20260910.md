# 机器人整体参数实验结论

## 结论

保留本轮开始时的 `team-first-v1` 默认权重。已经完成 7 套候选、三阶段共 **1,216 场、91,633 次行动**，没有找到通过独立验证、足以确认优于当前版的新参数。

这不是“原版已经全局最优”的证明。验证候选有微弱正收益，但目前样本不能排除偶然波动；不将其宣称为升级。提示、托管、机器人仍共用唯一正式策略，低档策略不恢复。

## 首轮结果

所有候选各对照本轮原版打 32 对／64 场同牌换边比赛。表内是候选所在队取得头游的比例，不是自身头游率，也不是对真人胜率。

| 候选 | 主要调整（相对原权重） | 本队头游 | P95 决策耗时 |
| --- | --- | ---: | ---: |
| 收尾优先 exit | 路线 ×1.3、散张 ×1.25、资源代价 ×0.8、控牌 ×0.85、点数保留 ×0.8 | 36/64，56.25% | 23.70 ms |
| 队友配合 support | 路线 ×0.9、对手走完风险 ×1.2、队友走完收益 ×1.3、喂牌 ×1.5 | 35/64，54.69% | 24.17 ms |
| 压制冲刺 pressure | 路线 ×1.1、控牌 ×1.3、对手走完风险 ×1.5、资源代价 ×0.9 | 34/64，53.13% | 24.21 ms |
| 综合 balanced | 路线 ×1.15、控牌 ×1.3、资源代价 ×1.2、喂牌及风险 ×1.25、温度 ×0.5 | 31/64，48.44% | 24.38 ms |
| 控牌 control | 路线 ×0.9、资源代价 ×1.15、控牌 ×1.6、风险 ×1.25 | 30/64，46.88% | 24.48 ms |
| 少随机 precise | 同优先级近似同分选择温度 ×0.25 | 30/64，46.88% | 23.32 ms |
| 保留资源 reserve | 资源代价 ×1.6、点数保留 ×1.2 | 28/64，43.75% | 23.87 ms |

温度只影响同一硬优先级内的近分候选，不影响必须出完、让队友、阻止对手走完等硬规则。上述值是对既有强/中/弱牌力和收尾阶段权重的倍率，不代表所有规则原先权重相同。

## 复赛与独立验证

首轮前两名在另一批种子上各打 64 对／128 场，都得到 **63/128（49.22%）**。依照预先声明的同分次序，P95 略低的 support 进入独立验证（24.518 ms，exit 为 24.593 ms；这个细小耗时差异本身不应解读为确定的性能提升）。之后没有再次调参。

独立验证冻结 support，在第三批种子打 256 对／512 场：

| 指标 | 队友配合候选 | 原版对手 |
| --- | ---: | ---: |
| 本队头游 | 263/512（51.37%） | 249/512（48.63%） |
| 候选头游率的配对 95% 区间 | 49.61%–53.13% | — |
| 实际决策数 | 19,174 | 19,167 |
| P50 决策时间 | 2.17 ms | 2.18 ms |
| P95 决策时间 | 23.31 ms | 22.97 ms |
| P99 决策时间 | 127.95 ms | 126.45 ms |
| 本轮最大决策时间 | 779.82 ms | 845.90 ms |

置信区间按整对同牌比赛重采样 10,000 次，保留换边比赛的相关性。下限没有严格超过 50%，所以未通过替换门槛。耗时、合法性、首手保炸门槛通过。

耗时是这台开发机 Node v26.7.0 的观测结果，包含生成候选、推断与评分，不含模拟真人等待。复杂牌局仍有长尾开销，本轮权重实验没有消除该瓶颈；不作真机帧率保证。

## 场景和信息边界

- 各轮级牌覆盖 2、5、9、Q、A，先手轮换，候选交换 A/B 队，同一种子的两场比赛中，各座位拿到的原始牌保持一致。
- 独立验证候选有队友 ≤10 张 6,547 次、上家 ≤10 张 6,774 次、下家 ≤10 张 6,368 次；强牌 1,425 次、中等牌 8,614 次、弱牌 1,227 次，另外 7,908 次走硬规则捷径。场景可重叠，不能相加当作局数或独立胜率。
- 测试器将其他玩家手牌替换为只能读张数的代理，任何暗牌读取直接报错；91,633 次动作均验证卡牌归属、不重复和可出性。零非法动作、零首手炸弹，全部在回合上限内决出头游。
- 模拟终点是第一名产生，不评估头游之后的双上收益、整场升级或真人策略适应。此次也未完整遍历 13 个级牌、所有房间规则和对手风格，不能声称全局最优。

## 代码和复现

- 正式参数唯一来源：`shared-core/src/ai/team/parameters.ts`。保留的 9 个倍率均为 1；`policy.ts` 读取这些冻结常量，底层牌力权重不变。
- 7 套候选仅在 `scripts/support/team-policy-experiments.mjs`，不进入 Cocos 生成目录、引擎配置或网络协议。离线脚本独立装载正式编译核心，不另写一份简化 AI。
- 参数拆分前后，通过 5 个完整头游过程逐手检查动作、分数、概率、随机检查点一致；自对弈同牌换边 hash 相同、恰好各赢一次。另以 4 场自对弈进行影子回放，检查兼容规则入口与线上 `transition` 的行动结果、轮次推进和公开历史一致。
- 协议及命令：`docs/TEAM_POLICY_TUNING_PROTOCOL_20260910.md`。全量原始数据（各场种子、先手、级牌、胜负、动作 hash、参数 hash）：`docs/TEAM_POLICY_BENCHMARK_20260910.json`。

本轮只更新共享源码、同步的 Cocos 代码及离线跑分工具，不发布微信新包，不更新线上服务器。

## 回归核验

- 核心 TypeScript 检查、18 个测试文件／129 项测试通过。
- 客户端完整 `pnpm test`、runtime/refactor/ci-core 类型检查通过。
- 参数跑分工具的 4 项自动测试通过；结果汇总校验种子、换边、每局结果、参数 hash、复赛候选及最终选择一致。
- 共享代码同步、架构体量、可达性健康检查、仓库隔离和 `git diff --check` 通过。

- 修正后 Node v22.23.2 的完整 `npm run test:server` 通过，包含四人／转蛋机器人、八人双桌、协议、持久化重启和结算。最终编译参数与归档报告的 `chosen: reference` 完全一致。
