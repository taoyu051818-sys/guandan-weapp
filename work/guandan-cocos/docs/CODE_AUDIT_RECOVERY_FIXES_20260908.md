# 第三轮抽查修复：入桌、退出与回执恢复

## 修复结果与责任归属

| 问题 | 修复 | 独立责任模块 |
| --- | --- | --- |
| 入桌响应丢失，重试换 requestId 导致一次性票据被拒绝 | 匹配入桌、本地重连在同一次操作内保留请求编号与正文；成功、放弃或销毁后清理。超时后的短暂退避仍接受迟到成功，旧 watchdog 不干扰新一轮尝试 | `network/LobbyEntryRequest.ts`；传输层只支持明确传入的已分配重试编号 |
| 退出保存失败后丢失席位和成功回执 | 保留已变更房间与退出回执，不伪装成回滚；同编号重试完成原退出。增加服务端自动完成任务，不依赖已返回大厅的客户端再次发送；房主两次保存均可恢复 | `server/weapp-room-exit.js`；复用 `weapp-room-expiry-jobs.js` 的串行、房间实例校验与取消能力 |
| 保存失败后重试只收到 actionAccepted，没有实际状态 | 保存确认后补发当前成员、准备、托管、deadline、贡还/牌局和结算快照；聊天回执不重播语音或聊天 | `server/weapp-command-publication.js`；继续使用按观看席位脱敏的 publisher |
| 已缓存回执随后被房间对象修改 | 回执缓存取得独立深拷贝，完成元数据也隔离；publisher 不再暴露 trustees、超时计数、投票、级数和结算的可变引用 | `weapp-accepted-action-store.js`、`weapp-room-publisher.js` |
