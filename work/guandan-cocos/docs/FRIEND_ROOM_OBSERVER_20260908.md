# 好友房内观战与换座验收 · 2026-09-08

## 入口和操作

- 好友房 → 体验设置 → 允许观战：禁止、实时、延迟。
- 秒级延迟支持 15、30、60 秒。兼容“1局”选项：下一局开始后展示上一局的已完成画面，不是逐帧回放。
- 开局前点击绿色“进入观战位”，释放自己的座位但不离开房间；点击空座下方“坐下”重新落座。换座会清除本人的准备状态。
- 房主身份与 p1 座位分离。房主站起后仍能管理候场、邀请，以及在四名玩家准备后开始游戏。
- 满座或开局后的邀请，在房间允许观战时进入观战位；不占用四个玩家席位。房间成员上限 12 人，包含观战者。
- 对局开始后锁定参与者，禁止通过站起、换座中途更换选手。机器人相关权限继续沿用原有房间能力，不在此次扩大。
- 观战直接使用现有牌桌：下方显示所选玩家手牌，点击头像切换。没有出牌、托管、准备下一局和快捷语按钮；不计入自己的对局成绩。

## 延迟和隐私边界

延迟在服务器执行，不是客户端收到实时数据后隐藏。服务器保留有界快照缓冲，只发出满足延迟条件的一份视角；另外三家的手牌用隐藏牌占位，贡牌内部信息不下发。

切换视角、重连均走恢复快照，不补播历史大特效。倒计时基于正在观看的时间线。服务端重启不会保存全部私有观战历史：没有满足延迟条件的画面时重新缓冲，不退回实时手牌。

实时观战是房主明确开放的信息权限；允许观战的私人房不能据此宣称具有比赛级防串通能力。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `server/friend-room-members.js` | 身份、房主、四个座位与观战角色转换 |
| `server/friend-room-observer-buffer.js` | 有界私有历史、延迟截止、单手牌投影 |
| `server/friend-room-observer-runtime.js` | 观战命令、票据恢复、roomView 发布与定时器清理 |
| `server/platform/friend-room-roster.js` | 开局时原子确认真正参赛的四人，避免换座后战绩串号 |
| `network/FriendRoomViewReceiver.ts` | 客户端身份/视角变更、恢复语义 |
| `FriendRoomWaitingPresenter` / `TableHudPresenter` | 候场操作、只读牌桌与视角提示 |

没有继续把新职责堆进 GameScene。客户端和服务端现有文件长度预算均保持原值。

旧 `ReplaySpectatorPageDomain` 拆除独立观战列表/详情展示，个人回放保留为 `ReplayPageDomain`。旧轮询策略移入 `migration/spectator`，不进入 Cocos 运行资源；平台事件上报等仍用于房间生命周期，不能当死代码删除。没有删除玩家对局数据。

## 发布与真机待验收

本轮未部署生产服务器、未上传微信。此功能涉及平台服务、牌局服务、Cocos 三端协议，必须先安排配套后端更新，再上传客户端；单独上传新包不能让旧后端支持站起/观战。

小程序导入目录：`work/guandan-cocos/build/wechatgame`。发布配置沿用既有已校验的 HTTPS/WSS 域名，不启用本地地址、不关闭微信域名校验。

部署后请用手机实际走一轮：

1. 房主启用实时观战，邀请四位以上成员；满桌后的成员进入观战位。
2. 房主站起，其他人换座、坐下并准备；房主仍能开始游戏。
3. 观战点击不同头像，确认只显示所选手牌、没有出牌按钮；返回/恢复不占座。
4. 再创建 15 秒延迟房，对比玩家端出牌与观战端出现的时间；缓冲期不得显示当前手牌。
5. 切后台后恢复，随后完成一局并四人准备下一局；观战者不计入准备人数，不获得自己的参赛战绩。
6. 禁止观战的房间不能站起或额外加入观战；已开局选手不能借观战更换参与者。
