# 代码抽查问题修复（2026-09-08）

范围：修复本次抽查的三个行为问题，收紧三个模块边界。不修改大厅/牌桌外观、玩法、动画资源或生产配置；不部署服务器、不上传小游戏。

## 行为修复

| 问题 | 修改 | 回归 |
| --- | --- | --- |
| 房主重连后仍被已排队的到期任务关房 | 任务执行时重新检查连接、房间对象身份及计时代次。取消、重新计时、销毁都能作废已排队任务 | 房主/空房重连；取消后执行；同 ID 重建；新计时覆盖旧任务；销毁 |
| 锁牌一次需要撤销两次 | 锁组创建与自动位置整理合并进同一次 commit；显式 groupIndex 不做自动位置整理 | 手动锁组与建议锁组的 revision、完整撤销、重做；原有指定位置回归保留 |
| 解散过期保存失败后投票丢失且不通知 | 持久化失败回退 vote 与 version；每秒重试完整业务操作，成功落盘后再发布 expired | 连续三次写入失败、恢复成功、取消/替换投票、关闭生命周期 |

计时与排队任务有效期由独立的 `server/weapp-room-expiry-jobs.js` 管理，过期业务条件留在 `weapp-room-expiry.js`。重试保持串行房间操作，旧任务不能清除新任务的计时记录。

这里修复的是指定过期操作，不宣称已将整个服务端改为数据库事务：当前仍使用全局 JSON 快照持久化；跨房间快照隔离和多进程写入仍不是它提供的能力。

## 模块边界

- `TableSceneNodes` 保留可空的 Inspector 输入，返回完整非空的 `BuiltTableSceneNodes`；`GameScene` 逐项显式绑定，移除动态 Object.assign 装配。只迁移类型/装配方式，不改变节点名称、坐标或交互。
- `TableMatchPorts` 用 Pick 声明协调器实际使用的方法；协调器不再接收整类的类型权限。它仍负责牌桌状态协调，并没有为了增加接口数量再增加一层运行时代理。
- `DataSnapshot` 只负责普通 JSON DTO 的深复制与递归只读冻结，不用于 Cocos 节点、Date、Map 或方法对象。
- `FrontPagePlayerState` 统一更新资料和仪表盘；外部不能直接替换 dashboard 或修改嵌套资料。旧快照不会因后续更新而变化。
- `DevelopmentPlayerStore` 保存单个开发会话的数据；同一套开发网关的 auth 与 playerCenter 共享该实例，不同实例互不影响。开发样例为只读模板，网关返回防御性副本，预览工厂返回独立只读快照。配置了生产地址时依然不使用样例兜底。
