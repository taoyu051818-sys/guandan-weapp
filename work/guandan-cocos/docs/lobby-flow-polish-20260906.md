## 实际修改

- 快速开始、继续牌局、正在恢复使用同一个右下主入口。没有活动牌局时仍匹配经典初级场；有恢复资格时调用真实恢复接口，不创建新匹配。
- 恢复忙状态由 `PlatformMatchRecoveryCoordinator` 的请求生命周期驱动。按钮原位更新文字、暂停输入；完成或失败后恢复输入。不使用假倒计时。
- 首次浏览器验收发现整页 reflow 会重播三张玩法卡的进场动画，且通用 disabled 皮肤使自定义按钮文字难读。最终改为原节点更新，没有动背景、卡片、商城和按钮尺寸。
- 匹配阶段明确区分 requesting、queued、cancelling、cancel-uncertain、entering、failed。正常排队保留等待时长和 7 秒补位说明，不虚构人数或成功率。
- 取消时先等待正在发出的 join 和服务端取消结果。若已分桌，解释原因后直接接入，不先跳回大厅。成功取消后的迟到回包不再入桌。
- 取消结果不明时可重新确认，也可“稍后确认”返回来源页；保留不确定凭证，下次匹配必须先处理，不能直接申请第二个匹配。
- 请求、轮询、无效入桌凭证失败时留在匹配页，提供返回与重新匹配。保留原队列、场次和返回来源。
- 已分桌的连接阶段不再显示“可随时取消”，身份确认期间不闪过好友房等待页。连接错误仍由既有房间错误及恢复流程处理。

## 模块边界

| 模块 | 责任 |
| --- | --- |
| `LobbyPageDomain` | 主入口状态原位更新，保留大厅视觉 |
| `PlatformMatchRecoveryCoordinator` / `GameScene` / `FrontPageController` | 将真实恢复 pending 状态接入前台，保持房间交接 |
| `MatchmakingPageDomain` | 匹配票据、取消、迟到回包与重试流程 |
| `MatchmakingPageView`（新增） | 现有匹配面板与分阶段可用按钮，无业务请求 |
| `MatchWaitingPresentation` / `MatchmakingErrorPresentation`（新增） | 等待说明及错误文案 |

同时删除匹配域未使用的 `pageButton`。没有提高文件体积预算；没有改规则、机器人策略、网络域名、音效或牌桌布局。
