# 一键理牌恢复简单规则

用户最终要求：撤回分阶段方案，不再自动处理普通顺子；删除评分选排法等复杂部分。

## 当前行为

- 使用现有固定规则优先级生成有限的牌型候选，单次遍历挑选不冲突的组合。
- 保留王炸、炸弹、同花顺、钢板、三连对及低对子三带二；剩余牌按点数归并。高对子不作为自动三带二的附件。
- 普通顺子不自动生成，也不为顺子拆对。选中合法顺子后仍可手动锁牌；已锁牌组不被一键理牌拆开。
- 点击直接完成规则理牌并切换为“复原”，不存在等待整手搜索的“理牌中·取消”状态。
- 不更改机器人/托管/提示的最高档决策，不更改不洗牌发牌算法。由于不再自动收普通顺子，旧版平均六手的统计约束不再适用。

## 退役范围

- 删除共享核心 arrangement 下的评分模型、特征成本、组合枚举器、解析缓存、全手搜索及规划 API，同时删除客户端生成副本。
- 删除客户端 HandArrangementPlanner、HandArrangementJob、HandLayoutCheckpoint、分段任务/缓存事务和对应等待状态。
- 删除旧评分调参、增量/快照耗时、六手规划跑分脚本及仅服务这些路径的测试辅助文件；历史测量文档保留并标记退役。
- 保留手动分组的规则判定、复原快照、锁牌保护和小型牌组显示元数据缓存；它们不执行排法评分或搜索。

## 验证

源代码检查：自动扫描旧 planner/job/weights API 的引用，运行类型、架构、共享核心与客户端完整回归。

已通过：完整 test:ci、typecheck:runtime、共享核心 build、微信 release 构建/finalize/verify。实际微信包验证确认 planner 与 HandArrangementJob 模块不存在。微信主包 3,302,334 字节，分包 13,743,105 字节，总计 17,045,439 字节。

Web release 构建/finalize/verify 同样通过，包括实际产物玩法回归和页面/音效/选牌/牌面检查。

新增 simple-hand-arrangement-regression.cjs：104 副经典/不洗牌手牌，验证单次调用完成、所有实体牌守恒、自动牌组合法、普通顺子不自动组合、重复理牌一致、复原和手动顺子锁牌/解锁。

本机 Node 26.7 源码测试，一次理牌处理（包含规则选组和分组状态更新）中位数 1.80 ms、P95 9.69 ms、最大 14.74 ms。非手机性能，也不含 Cocos 绘制及触摸派发；不承诺真机耗时。

真实 Cocos 构建验证检查旧 planner 和 job 模块确实不在包中，并执行理牌、复原、锁牌、提示与机器人决策回归。

## 手机验收

| 操作 | 预期 |
| --- | --- |
| 经典/不洗牌，发牌后立刻点一键理牌 | 按简单规则一次理好，按钮切换为复原 |
| 连续理牌/复原 10 次 | 无搜索等待、无漏牌/重复牌 |
| 混花色 3、4、5、6、7 | 不自动成顺子；可以手动选中并锁定 |
| 锁定上述顺子后理牌、复原、解锁 | 整组保持，锁牌与恢复功能正常 |
| 进贡/还贡阶段理牌，下一局再次理牌 | 权限和阶段规则沿用原功能，无上一局状态残留 |
