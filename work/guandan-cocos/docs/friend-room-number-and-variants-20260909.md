# 好友房：房号加入与新打法边界（2026-09-09）

## 本轮已实现

- 好友房设置底部：绿色“加入房间”、黄色“创建房间”。不恢复邀请中转页。
- 加入仅打开一个六位数字输入弹窗；数字键盘、输入校验、取消、键盘确认、防连点与页面关闭后的过期回调保护。
- 有效输入后直接进入牌桌等待；失败回到好友房设置，保留配置草稿。微信邀请卡片继续可用，长口令粘贴/复制入口不恢复。
- 新增 `POST /api/v1/friend-rooms/join-by-number`，必须登录，使用入桌幂等标识；同一用户网络失败重试复用标识。
- 服务端共用现有房间有效期、活跃牌局、黑名单、按顺序落座、满员、观战权限和签名票据校验。
- 房号持有者可以申请入房，房号本身不是入桌票据。每账号每分钟最多六次请求，限流表最多一万项，容量满时拒绝新键；目前为单平台进程内存限流，多实例需共享限流存储。
- 原卡片加入接口仍要求邀请凭证；房号加入返回值不泄露邀请凭证。没有卡片凭证的访客不显示无法使用的分享按钮。
- 入桌返回的房号必须和玩家输入一致，否则客户端拒绝进入。

## 模块职责

- `FriendRoomNumberModal`：输入、校验、按钮和关闭生命周期。
- `FriendRoomSettingsPresenter`：配置页草稿及弹窗接入。
- `FriendRoomFormUi`：底部双按钮布局，保持现有小圆角方框样式。
- `LobbyPageDomain` / `FriendRoomPlatformFlow`：直接入桌导航、异步请求、取消补偿。
- 平台 `friendRoomGateway`：输入/响应校验、HTTP 协议和幂等。
- 服务端 `FriendRoomService`：统一入房事务；`FriendRoomNumberLimiter`：请求频率和内存容量约束。

## 复式与转蛋：后续已推进

后续截图已补全积分表，用户确认复式输方为 0 分，不固定级牌由两桌每局共同随机。转蛋规则与联机流程、玩法规则弹窗已实现；复式仅完成规则说明与计分策略，八人双桌协调器尚未实现，入口明确标为筹备。详见 `friend-room-variant-rules-20260909.md`。下方为上一阶段的历史核验记录，不代表后续全部修改已通过或已上线。

此前等待补充的规则（现已补全）：

| 玩法 | 已确认行为 | 仍缺少的规则 |
| --- | --- | --- |
| 复式 | 八人、红蓝两队、两桌同时进行；对应方位同一副牌；默认固定打2，不升级不进贡；两桌首出方位一致，下一局顺时针；两桌结果累计；先结束的一桌可看另一桌 | 截图下方“排名倍数”计分表被截断；“不固定级牌”选项的级数变化规则未展开 |
| 转蛋 | 每局换队友；随机普通牌（不含王），两张分别归不同玩家时调整为对家，同一人拿两张时位置不变；或东方固定、另外三人顺时针轮换；固定2/随机级数，按指定局数结束 | 3分制/6分制具体名次分值、输方分值及累计规则未展开 |

以用户后续提供的完整计分表及明确确认为准，不将其他平台的地方玩法作为既定需求。

实现职责拆分：

1. 共享规则协议：新增独立模式及各自合法字段，客户端/平台/游戏服版本同步，拒绝不适用字段。
2. 转蛋：发牌前配队与座位重排、按用户而非座位累计积分；同步身份、托管、重连和观战视角。
3. 复式：八人房间协调器、两张子桌、相同牌序及首出方向、两桌局间屏障、红蓝队累计计分；确保未完成桌手牌不会通过已完成桌视角泄露。
4. 最后接入配置标签和等待/结算界面，加入八端并发、重复结果、断线恢复、机器人和观战回归。
