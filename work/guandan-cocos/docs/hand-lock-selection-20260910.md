# 锁牌交互修复（2026-09-10）

## 原因

- 原按钮先进入独立锁牌草稿模式并清除正常选牌，因此不能直接锁定用户已选中的牌。
- `HandGrouping.getPlaySelectionForCard` 只判断是否点中叠牌最下方，没有判断 `locked`，导致锁组上方成员仍可单独选中/取消。
- 提示策略把锁牌当作软保护，在没有其他合法解时可能选择部分锁组成员。

## 当前规则

- 使用唯一的正常选牌集合，不再保留锁牌草稿、确认/取消模式及其覆盖层。
- 未锁牌且选中至少两张、通过当前规则的独立牌型校验时，按钮显示“锁牌”，点击立即锁定。锁牌不要求压过上一手。
- 选中一个或多个完整已锁牌组时，按钮显示“恢复”；恢复只解除锁定，保留当前选牌。一键理牌模式可以重新排成未锁的智能组合。
- 空选、单张、非法组合、过期牌 ID、锁组与散牌混选均不改变牌组，并提示如何选择。
- 锁组任意成员的点击或拖动选择都按整组处理；普通未锁叠牌仍允许逐张选择/取消。
- 同花顺快捷选择使用正常选牌集合，可直接锁定或出牌；提示过滤所有拆锁候选。没有不拆锁的提示时提示先恢复牌组，而非自动拆锁。
- 托管、已出完、提交中、贡还和结算阶段仍阻止锁牌；一键理牌和贡还单张选择不变。新一局清除旧锁组。

- 全量客户端 `pnpm test` 通过，包括新单步锁牌、任意组员整组选/取消、恢复单张、混选/失效输入、跨回合、提示不拆锁测试。
- TypeScript 运行时检查、234 模块架构检查及 355 文件健康检查通过。
- Web 实际鼠标点击：对子底牌选中 → 锁牌 → 顶牌整组取消 → 顶牌整组选中 → 恢复 → 顶牌单张取消，全部通过。测试仅使用内存牌局，刷新已移除，无线上房间/账号写入。
- Web 预览已更新；微信包构建和包体核验通过，主包 3.18 MiB，总计 16.28 MiB。未上传微信平台，微信真机手势仍需验收。

锁牌仍是客户端手牌整理功能，不是服务端规则；不改变托管/机器人算法的出牌权限。

## 后续模型收口（2026-09-10）

- `HandLockDecision` 统一为 `lock / unlock / unavailable(reason)`。工具栏、提示和执行校验消费同一模型，删除旧 `start/commit` 动作类型和 HUD 重复定义。空选、无效牌 ID、非法组合、部分锁组、混选和阶段阻塞都有明确原因。
- `getLockDecision` 只读，每次仅获取一份分组快照；`applySelectionLock` 执行时重新查询当前决定，避免使用过期的按钮判断。
- `HandInteractionStateMachine` 改为纯函数 `resolveHandInteraction`，删除可变派生状态及其同步/重置流程、未使用的回合布尔量。模式和阻塞原因改为判别联合，非法搭配由 TypeScript 拒绝。
- `resolveHandCapabilities` 统一控制选牌、分组、理牌、出牌和提示；`canSelectTributeHand` 统一贡还参与人判断。非自己回合仍可预选和锁牌，提示/出牌仍须轮到自己；贡还等待时可理牌，选牌则受参与人和联机 deadline 对象约束。
- 修正旧状态判断冲突：贡还快照携带上一局 `finishedPlayers` 时，不得禁用新一局的贡还选择。真正出牌阶段的完成者仍不可操作。
- `cancelManualSelection` 更名为 `clearSuitPreview`，只清花色预览、不清规则选牌；调用方与能力契约同步更新。
- 增加 48 组阶段/回合/等待/托管/完成状态交叉测试和 72 组贡还参与人/截止对象测试，并验证决定查询无副作用、执行重验、类型不允许矛盾状态。
- 本轮全量 `pnpm test`、`typecheck:runtime`、架构与健康检查通过；Web 构建及构建版选牌回归通过。没有改动服务端规则或重启线上服务。
- 微信包重新构建并通过运行时配置、启动/恢复模拟回归及包体核验：主包 3.17 MiB、总包 16.28 MiB。未上传，真机手势本轮未验收。
