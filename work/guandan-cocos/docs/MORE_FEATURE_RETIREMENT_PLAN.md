# “更多”功能收束与退役计划

更新日期：2026-08-07

## 现状

- 正式“更多”提供“游戏设置”、“延迟观战（实验）”30 秒公开事件示例和“快速开始·人机测试”。人机测试固定为最高难度、三名策略机器人；开发构建在存在固定测试牌局 fixture 时，额外提供“牌桌特效测试”。
- 大厅头像/资料栏是个人中心入口。个人中心统一读取八位账号、钱包积分和 `rating.comprehensiveScore`，并承载“赛季任务”“我的牌谱”。
- 开发网关的任务、牌谱、观战都明确标为演示或模拟；开发任务没有可领取操作。正式平台配置后才允许领取真实任务奖励。
- `showStats`、`stats` 路由、双明牌教学入口、摸牌定庄 `GroupingController` 及 GameScene 接线已删除。
- 设置页不再展示没有消费者的视觉主题开关；`visualTheme` 存储字段仍保留，避免旧存档反序列化失败。
- 商户 Cocos 页面、网关和服务端能力暂时保留，但普通玩家入口不可见。

## 分阶段计划

### 阶段 0：入口冻结（已完成）

用 `tests/more-feature-retirement-regression.cjs` 固定“更多”白名单、个人中心导航、开发数据标识、设置兼容字段、Grouping 删除和商户隐藏边界。

### 阶段 1：真实环境验收

在已配置平台账号上验证个人中心的账号、积分和综合分来自同一登录用户；验证任务领取幂等、牌谱访问控制、观战延迟与隐藏手牌边界。开发包和正式包分别确认牌桌特效测试的门禁。

### 阶段 2：商户能力迁移

产品确定独立商户端或受角色保护的运营入口后，将现有 `MerchantGateway` 和页面迁移到独立模块。新入口必须先完成登录角色、审计、限额、撤销与对账设计，不能重新放回普通玩家“更多”。

### 阶段 3：遗留代码删除

独立商户端上线并完成数据/接口兼容期后，再删除 Cocos 内的商户页面和路由。删除前需确认服务端调用方、生产日志、灰度版本和回滚版本均不再依赖旧客户端路径。

## 依赖与放行条件

- 平台 API 必须稳定返回严格八位 `accountId`、钱包快照和 `rating.comprehensiveScore`。
- 任务、牌谱和观战继续使用当前鉴权与公开信息模型；客户端不得推断隐藏手牌。
- “快速开始·人机测试”是明确保留的正式测试入口，必须始终固定最高难度；`cc/env` 的 `DEV`/`DEBUG` 门禁和 EffectLab fixture 列表只负责阻止正式包创建牌桌特效实验室入口。
- 删除 Cocos 组件前必须扫描 `.scene`、`.prefab` 和 `.meta` UUID 引用。本次删除的 `GroupingController` UUID `c95ae722-fb7c-4344-9cb6-64545b31a14d` 没有序列化引用。

## 回退方案

- 导航问题可单独回退 `FrontPageController` 与 `PageRouter`，不需要回退平台或服务端数据。
- 若产品重新批准摸牌定庄流程，应从版本历史恢复独立组件和测试，并重新完成场景 UUID 审计；不要复用手牌展示层 `HandGrouping`。
- 商户迁移失败时保留当前客户端代码和服务端接口，但继续维持普通玩家入口隐藏；回退不得绕过角色鉴权。
- 视觉主题 UI 不应作为回退手段。旧 `visualTheme` 字段仍可读取，因此旧存档无需迁移或清理。

## 数据保留

- 保留 `GameSession` 的 `visualTheme`、`playerStats`、`recentMatch` 和本地八位账号键，避免破坏旧存档与回退版本。
- 保留平台的钱包流水、比赛结算、综合分、任务领取、牌谱/观战公开时间线和商户数据；本计划不删除、重算或迁移服务端数据。
- 模拟数据仅用于开发展示，不得写入真实钱包、战绩、任务或牌谱。
