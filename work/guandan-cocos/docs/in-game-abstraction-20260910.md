# 牌局职责与模型收紧（2026-09-10）

本轮仅重构牌局实现，不调整玩法、布局、路由或赛事页面流程。

## 单一职责

- 服务端 `weapp-room-action-executor`：手动、托管、机器人共用 PLAY/PASS/进贡/还贡/开始本局的规则应用、统计、版本推进、结算消费和提交发布路径。
- `weapp-match-lifecycle`：保留时钟、AI 决策、失败重试与回滚、下一局编排及持久终局重试。已落盘的动作若发布失败，不回滚成旧牌局。
- 八人双桌保留独立房间编排和两桌屏障，不强行套用普通房的数据结构。
- `RoundViewState`：按 playing/tribute/settlement 区分必需数据，禁止缺少进贡或结算数据的投影进入展示。旧拆包兼容仍留在网络接收/投影边界。
- `GameManager`：状态不能直接替换；接收快照时复制并深冻结，防止原始数据包或界面改写权威数据。为兼容现有核心只读算法签名，深层不可变由运行时冻结保护；不在每次选牌和渲染时复制全量状态。
- `TablePhasePresenter`：承接操作按钮显隐、排列、结算显示和阶段进入动画，不订阅网络，不推进规则。
- `TableTurnClockProjection`：仅根据快照、服务端截止时间、席位和当前时间计算计时信息。控制器不再读取 Label.node.active 作为计时条件。
- `HandGroupingHistory` 及其 meta、undo/redo API、canUndo/canRedo、历史记录写入已移除。一键恢复继续使用 HandWorkspace 的基准快照；服务端移除的牌不能被旧快照恢复。

## 防回流

收紧协调器、倒计时控制器、服务端生命周期及指令处理器的行数预算，为新模块设独立上限。没有新增通用事件总线、路由框架或每按钮策略类。

新增回归覆盖：阶段完整性、快照不可变、截止时间纯投影、退役边界，以及五种手动/自动指令的一致处理、拒绝无副作用、持久化失败不发布、发布失败不回滚。
