# 微信理牌与提示兼容性修复

2026-09-10。本次交付本地源码与重新构建的微信／网页包；未推送 GitHub、部署服务器或上传微信。手机实测尚待验收。

## 根因与改动

Cocos 3.8.8 当前构建链的 loose 数组展开将 `[...map.values()]` 编译为 `[].concat(map.values())`，不会展开 Map 迭代器。合法候选被当成迭代器对象，过滤后变为零；整手规划中的 Map 条目也不是预期数组，随后抛错。这不是按钮权限或房间规则导致的。

直接运行旧微信成品包时，三张散牌得到零个合法候选；新增成品回归在这一断言失败。修复后相同测试得到三个合法候选、三个分组、三个提示。

- 共享核心的候选枚举、分组计数、牌力／路线／概率推断，以及提示种子字符串展开，改用 `Array.from` 显式转数组。保留策略、权重和搜索预算。
- 同类客户端清理逻辑中的 Map 展开一并处理；节点子数组快照使用 `slice`。
- 已同步 Cocos 生成核心；不直接手改生成副本。
- 新增类型检查回归，检查共享核心和客户端共 285 个运行时源文件中的数组／调用展开，拒绝 Map、Set、迭代器、字符串及不能证明是数组的类型，允许数组、只读数组、元组和数组约束泛型。接入默认测试和 CI。
- 提取成品模块加载器，微信启动测试与理牌／提示测试共用。后者是微信及网页正式包验证的必检项，缺失包会失败，不跳过。
