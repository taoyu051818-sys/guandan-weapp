## 唯一推荐的微信发布流程

先审查并提交源码，确保 `git status --porcelain --untracked-files=all` 为空。

```sh
node scripts/wechat-release.mjs prepare YYYYMMDD-reviewed-release X.Y.Z.N
node scripts/release-compatibility.mjs https://api.yutechhn.cn/guandan
node scripts/wechat-release.mjs upload YYYYMMDD-reviewed-release X.Y.Z.N '已审核的版本说明'
```

命令中的 release-id 和版本号必须换为本次真实值。`prepare` 跑回归、重新构建 Web/微信、finalize 和制品核验，保存日志及哈希清单；不能拿旧包直接创建上传凭证。默认 Creator 3.8.8，可通过 `COCOS_CREATOR_BIN` 指定安装位置；`WECHAT_CLI_BIN` 指定开发者工具 CLI。

`release-artifacts/<release-id>/` 是不入 Git 的发布证据目录，应备份到受控发布归档；其中 `manifest.json` v2 记录提交/tree 和核心构建、两个客户端构建、服务端、后台文件清单。管理端清单用于完整性核验，不表示测试/文档会进入服务端部署包；实际部署仍用白名单打包器。

上传前从**待上传包**读取 API 地址并验证 HTTPS/合法域名，不接受随意指定的测试服务器。只读请求 `/api/v1/capabilities` 和三个大厅入口，验证当前合同主版本；功能可以维护/关闭，但字段和路由必须存在。先部署配套服务器再上传客户端，不因暂时 404 自动降级或跳过检查。

`upload-attempt.json` 防止同一包失败后盲目重试。退出码 0 不足以证明成功，还需要 CLI 明确成功标记、无错误标记、提交和制品前后未变；不确定时人工核对公众平台，不能删除记录后直接重传。

`upload-result.json` **只记录开发版上传状态**。体验版选择与手机验收单列为未确认/待验收，没有自动填“已发布”。目前不能技术阻止持有权限的人直接调用微信 CLI；团队流程应统一使用这个入口，紧急绕过必须记录原因和核验结果。

## 存储容量与审计归档

JSON writer 启动和成功落盘后输出不含业务内容的 `PLATFORM_STORAGE_CAPACITY` 告警。按阈值变化去重：平台快照建议预算 64 MiB、审计 32 MiB/10 万条，80% 预警、100% 严重。64 MiB 是建议预算，不是经过压测的容量承诺，也不会主动阻断业务。既有审计硬限制不变。

可对私有快照运行：

```sh
node scripts/archive-operations-audit.mjs inspect /PRIVATE_BACKUP/platform.json
node scripts/archive-operations-audit.mjs prepare /PRIVATE_BACKUP/platform.json /PRIVATE_BACKUP/new-audit-bundle 2026-08-01T00:00:00Z
node scripts/archive-operations-audit.mjs verify /PRIVATE_BACKUP/new-audit-bundle
```

`inspect` 仅输出计数、字节和状态；预警/严重退出码 2，适合现有运维监控采集。本轮未安装监控代理或定时任务。

`prepare` 只归档指定日期之前的**连续前缀**，至少保留最近 1000 条，生成 0700 目录、0600 文件：完整原快照、归档审计、新快照和 SHA-256 清单。禁止放入仓库、符号链接输入、覆盖已有归档；业务数据、身份、幂等收据和 TOTP 重放计数必须完全不变。失败残留目录没有完整清单，不能采用。

**不会替换线上文件。** 实际采用需独立维护窗口和授权：停止唯一 writer → 备份全部数据 → 校验源 SHA 与 bundle 一致 → 验证归档守恒 → 按现有耐久写入/权限流程替换快照 → 重启并检查。若在线写入使源 hash 变化，必须重新生成，不能覆盖新数据。保留完整源备份和归档，不清空 auditBytes 绕过容量限制。反馈正文/幂等记录不在本次自动清理范围内；接近其限额时应评审数据库迁移。
