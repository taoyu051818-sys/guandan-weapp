# 随机级牌单局与好友房赛制（2026-09-07）

## 行为约定

- 经典匹配（quick、四档 classic 底分场）：服务端在开局时等概率抽取 2～A 的一个级牌，四人共享。按一局名次结算，不延续升级、不进贡。随机到 K 或 A 也不执行冲 A、降级、过 A 规则。
- 经典匹配的一局就是一个完整 matchId。结算后停止回合计时与准备，结果走原有幂等上报、战绩与底分结算流程。再来一局先回到选场界面，创建新的匹配，不在已经结算的旧 matchId 下再次发牌。
- 好友房「定局玩法」：1 / 4 / 8 / 12 局快捷选项，1～32 整数自定；每局随机 2～A 或固定任一级牌。按双下 3 / 4 分配置累计计分，头游加三游 2 分、头游加末游 1 分，不升级、不进贡。未到局数上限时四人准备下一局，最后一局显示全场结果。
- 好友房「传统升级」：从 2 打到过 A，双下升 3 / 4 级，可选进贡或不进贡。隐藏的局数字段不再构成终止条件；配置了总时长时仍按既有房间时限处理。
- 既有 20 / 40 / 60 秒出牌时限、托管、观战、理牌、互动和牌序选项保留真实实现。未开放的复式、转蛋、斗地主入口不放在此次配置页中。

## 兼容与权威边界

新增可选字段 `format / levelMode / levelRank / tributeEnabled`。旧房间没有这些字段时继续使用历史升级合同，既有 4～32、4 的倍数的局数校验不变，不在重连时偷偷换规则。

规则核 MatchState 保存 `matchFormat` 与已经抽出的 `currentLevel`。普通匹配票据新增签名 `matchMode`，重入票据保持该值，牌局服校验所有座位的一致性。固定赛事票据不强行套用经典单局策略。

随机源只在创建新局时调用；客户端只渲染服务端状态，不自行抽级牌。随机允许连续两局抽到相同级牌。贡还流程在定局或关闭进贡时直接跳过，不生成历史贡牌动画。

好友房网关与服务端共用规则归一化；创建请求的幂等键包含新字段，避免不同赛制被误认为同一请求。拒绝“定局但进贡”“传统升级却随机级牌”和无效级牌组合。

## 界面

保留陵水背景、小鸡商城、大厅留白与现有按钮材质。好友房左侧仅保留两个可用赛制，中央切换基础规则 / 体验设置，规则摘要实时变化；规则列表滚动，创建、加入与返回固定在滚动区域外。

结算展示四名玩家及真实名次。定局结算显示本局得分，不出现「升0级」。经典单局显示「再来一局 · 选择场次」，好友房中途保留四人准备进度。

## 真实构建发现的问题

新滚动表单需要 Cocos Mask，但原 WeChat 2D 裁剪配置关闭了该模块。TypeScript 与模拟控件测试通过仍不能保证正式包可运行。本轮通过旧版对照和临时诊断页构建跟踪定位到缺失组件；开启 `mask`，并增加引擎配置回归断言。临时诊断只在测试页中使用，不进入正式源码和包。
