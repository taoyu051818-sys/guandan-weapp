## 模块与一致性

- `shared-core/src/lib/variantRules.ts`：配队、物理顺序、计分表与计分函数。
- 核心 `matchFormat/settlement/tribute`：模式校验、独立个人累计、下一局；转蛋不升级/不进贡。
- 服务端 `match-format-policy/weapp-match-lifecycle`：发牌前选择配队牌、权威状态与结束事件。
- `platform/friend-room-personal-scores.js`：按已签名房间格式校验个人积分范围及总和，不接受客户端自报分。
- `FriendRoomRuleContent/FriendRoomRulesModal/FriendRoomModeTabs`：规则内容、弹窗、配置标签各自独立。
- 牌桌 HUD、出牌区、时钟、气泡、AI 均按状态 turnOrder 定位。PlayerId 和认证身份保持不变；只修改物理顺序和当局队伍。
- 结算展示个人本局分与累计分；对局记录使用当局实际队伍判断胜负。

## 验证

- 共享核心：16 套、82 个测试通过；覆盖 52 种配队牌、所有名次和两种积分制、三轮换队及序列化恢复。
- 新增四个真实 WebSocket 客户端的两局回归：顺时针/3 分和抽牌/6 分、局间重入、个人累计、最终结算、对手手牌隐藏通过。
- 签名个人积分事件：缺失、篡改、越界、幂等和持久化测试通过。
- TypeScript、架构大小预算、健康清单及服务端静态检查通过。未放宽代码体积预算。
- 在 874 × 402 Cocos Web 横屏检查规则分类、滚动积分表与关闭按钮。
- 客户端 77 项逐项执行：74 项初次通过；两项因模块职责迁移而更新检查位置后通过，一项旧出牌区间距断言从 99 更新为已确认布局的 79 后通过。没有改动已确认的出牌区布局。
- 平台全套回归通过；游戏服余下 29 项逐项通过。延迟观战重启测试曾在 3 秒启动等待窗口内超时，停止并行 Web 构建后单独重跑通过；实时观战测试通过。
- Web 和微信正式构建完成，微信包及生产端点核验通过：主包 3,090,349 字节，总包 16,523,518 字节。核验含模拟启动/恢复，不等于真机登录和线上后端验收。

## 未完成与发布次序

复式仍需独立八人协调器、两张子桌、相同牌序、首出方向同步、局间屏障、红蓝跨桌计分、先结束一桌的观战权限，以及八端并发/重连/重复结果回归。

转蛋上线前先部署平台和游戏服，再发布同版本客户端。真机验收：创建转蛋 → 微信邀请 → 两局换队 → 后台恢复 → 最终个人积分。没有自动上传、部署或提交代码。
