## 验证结果

隔离后的工作区与仅由 Git 暂存内容导出的干净目录均通过：仓库边界、共享源同步、架构/健康检查、78 项共享规则测试、76 个客户端回归脚本，以及服务端静态/平台/权威牌局完整回归。干净副本从锁文件安装依赖，不携带旧工程或原工作区 node_modules。原工作区的 Creator 完整类型和迁移类型检查也通过。

提交前对暂存内容进行凭据模式及敏感路径检查，未发现真实密钥；唯一带 userinfo 的 URL 为明确用于拒绝非法 URL 的测试数据。对当前已有的大量修改一并形成可追溯发布基线，不把这批全部改动误称为本次历史工程隔离单独产生。

GitHub 首轮服务端 CI 发现启动顺序缺口：静态导入检查在 shared-core 构建前执行，而本机串行验证先运行客户端测试，已生成该目录。已补上服务端工作流的显式共享核心构建步骤，不放宽缺失模块检查；服务端现可独立于客户端工作流运行。

首轮客户端 CI 同时发现两项牌面测试直接动态导入 TypeScript，仅在较新的本机 Node 上可用。两项测试改用既有的 TypeScript 测试加载器，保留所有牌面、素材与哈希断言；CI 仍在 Node 20 上执行，没有通过提高版本或跳过测试规避兼容性检查。

服务端完整 CI 随后暴露好友票据冒烟测试的异步竞态：踢人后未等平台离席回执落盘就假定新用户可入座。测试现用受控回执先验证替补在待确认阶段被拒绝，再确认回执落盘后同票据可入座；没有放宽服务端入桌安全限制或单纯拉长超时。意外协议错误也会即时报告具体错误码。

终局冒烟测试另出现固定端口 39120 的子服务启动超时。原测试丢弃了子进程日志，无法据此断言唯一根因；现保留有界启动日志、进程退出立即报错，并将这组固定重启端口移至 Linux 默认临时端口范围外的 19017–19024，避免与先前测试的 HTTP/WebSocket 临时连接竞争。生产端口、业务逻辑和验收断言不变。
