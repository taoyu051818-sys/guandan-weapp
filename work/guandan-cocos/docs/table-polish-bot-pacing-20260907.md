- 删除日常出牌、不要、贡还、开局过程中的“等待服务器确认”文案；网络失败、超时和取消失败仍有可处理的反馈，不能把真正错误吞掉。

## 最终层级（按用户本轮两次补充）

从下到上：桌面出牌 → 我方手牌 → 飞牌、特效 → 出牌/提示/不要等操作按钮 → 弹窗。

`GameScene` 使用 `TableLayerOrder` 统一排序，不重设手牌父节点、不改触控坐标系。`TableHudPresenter` 把回合按钮挂到 HUD 操作层，HUD 在特效之上；弹窗由自身控制器置顶。

左右出牌由 `PlayedCardLayout` 计算：以头像内侧边缘为锚点，向桌内展开，牌组张数变化不改变靠头像的一边；卡牌底边和侧边头像底边对齐，间距 18 个场景单位。侧边位置按安全区变化。不是在所有张数下把整副牌中心锁死在同一坐标。

我方、对家继续共用上下相邻的中间出牌列。飞牌和最终静态牌使用同一几何算法、0.8 倍落桌尺寸，缩小在落桌前完成。

## 昵称与服务端节奏

- 字库来源：MIT 的 [XadillaX/chinese-random-name](https://github.com/XadillaX/chinese-random-name)，固定提交 `be80a1afe49e6a376626c803c4b1e31079be406d`。仅采用审核过的姓氏子集和组合思路；短昵称词汇另写，不包含算命描述、真实用户资料和原生随机数依赖。
- `server/player-nicknames.js` 用身份种子生成稳定、短小的虚构昵称；同桌去重，恢复、重启保持一致。许可证保存在服务端 `third-party/chinese-random-name.md`。
- 保留 `isBot`、签名席位、审计、权限和隐私边界，不增加“真人”身份声明。
- 普通动作按基础延时随机浮动；生产默认 650ms 对应约 488–975ms。
- 炸弹（含同花顺、四王和逢人配组成的炸弹）或拆对子/三张/炸弹，按回合开始计时随机 1.2–3 秒，受回合 deadline 上限限制，不是基础延迟后再加 3 秒。
- 公开回合 deadline 和内部自动出牌唤醒时间分离，经典场公开仍为 20 秒；私有房遵守房间设置。
- 决策只计算一次，待出 cardIds 和执行时间随房间持久化。恢复不重新抽延迟；执行仍验证权威状态，过期回调不跨回合生效。表现随机数与洗牌、AI 随机数流分离。
