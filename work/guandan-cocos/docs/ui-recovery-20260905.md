## 已实现

- 大厅：保留陵水海岸，右侧纵排横向玩法卡；经典场/好友房使用无文字插画，标题由代码绘制；比赛入口弱化并标明筹备中。
- 左栏：商城、活动、规则采用同一线性图标族；取消“活/规/续”文字代图标。保留真实可恢复牌局入口。
- 文字：新增 CoastalUi，在实色面板上使用无粗描边文字；没有全局改写老 UI/扑克牌字体。
- 牌桌：我方/对方级数放在左上角返回按钮下方；理牌/锁牌/聊天回到底边，同花顺工具为我方信息留出位置。
- 出牌区域：我方落牌点由 `(0,-82)` 调至 `(0,78)`；侧方由 y=0 调至 y=36；对家落牌点改为 `(72,185)`，与对家信息分开。飞牌终点与正式落牌继续共用 getActionWorldPosition。
- 回合操作：HUD 与贡还等备用操作共用 `(0,44)` 锚点，避开多层手牌的上沿；倒计时与动态按钮逻辑保持不变。
- 不出：只显示“不要”文字，去掉额外纸牌式底框。
- 机器人：占据服务器机器人席位的玩家不再被标为离线；真实人类断线判断保留。
- 商城：恢复抽纸、洗衣液、面巾三类示例商品及详情。详情返回商城，目录返回大厅；兑换仅展示开发中，不发订单、不扣积分。
- 比赛：恢复可阅读的赛事介绍；不展示虚构日期、报名人数、奖金。公开入口只进入 preview，不进入遗留报名流程。
- 匹配：四个“待分配”占位，明确分配前不代表已有人入座；多行状态使用 116 逻辑单位高度，不再由空单行标签压缩。取消和过期票据对账不变。
- 匹配成功：等待室区分 match/friend；匹配入桌不再显示“好友房（仅展示）”或假房主标识。
- 结算：四列名次、队伍关系、逐人准备状态和升级信息。准备按钮仍由原协调器操作权威状态；面板位于落桌卡牌上方，操作按钮位于面板上方。

## 选牌边界

当前 CardView 的设计是平面滤色选中，而不是抬升/改变层级。本轮不修改这一输入与叠牌约定。浏览器测试在多次其他玩家出牌之后，点击后确认 snapshot.selectedCardIds 与 HandController 的选中集合一致，并观察到选中牌滤色。

不要把自动超时出牌后清空选中集合，误判成选牌失败。验收时应记录点击后即时状态，并区分托管、贡还权限和回合自动推进。

## 重叠验收方法

使用地址参数 `?layoutAudit` 启用只读浏览器接口 `window.__guandanLayoutAudit.snapshot()` 或 `.warn()`。微信缺少浏览器 API 时该接口安全跳过，不能阻塞大厅启动。

报告包含交叠宽高(px)、面积(px²)及双方安全区域占比；安全框包含未实际画牌的预留空间，不能将警告数量等同于视觉缺陷。审计不移动、不隐藏任何游戏元素；最终结合牌角可读性、点击反馈和截图判断。

首轮实际 874×402 采样中，我方手牌/我方出牌安全框重叠 170.7×81.9 px，13987 px²，占手牌区 12.35%、出牌区 100%；对家信息/对家出牌区重叠 46.3×55.8 px，2583.3 px²，占双方 29.60% / 18.47%。调整落牌位置后的复测这两项均不再相交。不同手牌、展开记牌器时仍可能出现其他合理交叠，不保证所有状态零警告。

最终构建再以 26 张长叠牌状态复核：手牌/我方出牌的预留框交叠为 170.7×23.6 px，4036.3 px²，占双方 3.10% / 28.86%；手牌/操作按钮预留框为 275.8×37.2 px，10249 px²，占双方 7.88% / 59.42%。截图中按钮处于牌组上方的空隙，没有覆盖实际牌面。这说明矩形包围框会把牌组之间的空白也计入，不应将前一状态的零交叠泛化成所有牌局零交叠。对家信息/对家出牌、我方信息/同花顺工具在该次采样中无交叠条目。
