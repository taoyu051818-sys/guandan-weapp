# 16 人赛事开放与页面重做

## 本次明确的规则

- 免费 16 人赛事，报名后需检录；满 16 人锁定名单，服务端分配 3 轮 × 4 桌。
- 每桌每轮随机一个 2—A 级牌，只打一副，不升级、不进贡。不同桌不要求同牌或同级牌（不是复式）。
- 个人头、二、三、末游计 3、2、1、0 分；三轮累计。为保证第三、第四名真实可比，赛事专用 individualRanking 要求打出第三名才结束，双上不提前结算。
- 同分顺序沿用服务端：对手分、胜场、头游次数、稳定账号顺序。
- 同一赛事不重复同桌；每轮四桌都结束后推进下一轮。
- 三轮结束前 8 标记晋级，不自动进入淘汰赛。赛事不补机器人。

## 已实施

- 大厅赛事入口进入新赛事中心，不再弹“筹备中”。只展示免费、固定 16 人的已支持赛事；未开放原有收费样例。
- 使用现有陵水背景、赛事奖杯素材、统一小圆角方框与按钮尺寸；赛况、排名、规则分区，排名四人一页，显示真实晋级状态。
- 报名、检录、入桌动作分离，按钮禁止重复提交。退出/切后台后旧请求不重新打开页面；数据不变的轮询不重建 UI。
- 复用匹配模块及固定桌票据；首次签发、过期重签均携带匹配赛制。冷恢复携带队列来源，赛事结算返回赛事中心，不误进经典场。
- 个人赛事结算显示本桌名次和个人得分；总排名以平台累计结果为准。
- 新职责独立为 TournamentCenterModel、TournamentCenterController、TournamentCenterView、TournamentApiGateway 和独立解码器。迁移区旧适配器仅转出新的实现，无重复网络逻辑。

## 核验

- 核心测试 16 文件、86 项通过，覆盖双上后继续竞争第三名及旧普通场规则不变。
- 客户端默认 80 个回归脚本通过；新增赛事状态、免费报名、重复点击、轮询不重绘、前后台隔离、晚到响应、返回赛事及冷恢复来源测试。
- 服务端检录、分桌、编排、HTTP 签名结果的完整三轮契约通过；固定票据赛制、重签、单副终局及现有好友房回归通过。
- 运行时类型检查、架构、健康检查与 37 个共享模块同步通过。
- Cocos 浏览器实际渲染检查：报名、检录、规则、排名与翻页。界面验收数据仅注入浏览器内存，不写线上账号/报名。
- 微信构建和原生环境模拟校验通过，未上传微信后台。

## 发布与边界

- 最终服务端版本：20260909-tournament-ranking，保留旧代码版本及数据备份，切换前检查活动连接与未结束牌局。
- 发布后确认两个服务 active、NRestarts=0；公开健康检查 200，未授权资料接口 401，开发登录 403，WSS 应用协议与不可信 Origin 拒绝检查通过。免费赛事保持 open、检录 0 人，没有写入验收报名数据。
- 本轮没有组织 16 台真实手机参赛；HTTP 三轮结果测试使用签名结果夹具，不能代替真机全流程验收。
- 异常牌桌会阻塞赛事；尚无管理员补赛/重开、自动淘汰赛或新一期赛事自动生成能力。
- 不含收费报名/退费流程。此阶段仅适合组织好的免费 16 人赛事。
- 客户端需上传本次新微信包才能看到新页面；仅服务器部署不会更新已发布客户端。
