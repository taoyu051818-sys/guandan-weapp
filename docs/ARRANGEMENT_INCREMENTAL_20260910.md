> 已退役的历史记录：2026-09-10 按用户要求删除一键理牌评分/搜索/分段预热，恢复简单规则且不自动组普通顺子。本文测量及原复现脚本不代表当前版本；相关旧脚本已清理。当前说明见 [简单规则恢复](SIMPLE_ARRANGEMENT_RESTORE_20260910.md)。

> 历史记录：本文的逐帧调度及建议数组缓存已被后续完整布局快照方案替代。当前行为与包含定时器等待的测量见 [完整布局快照](HAND_LAYOUT_SNAPSHOTS_20260910.md)。以下 CPU 数据保留原始测量口径，不代表真机点击耗时。

## 范围与行为

本轮只改变理牌的计算方式、缓存及交互反馈。规则、评分权重、搜索节点预算、分支上限、不洗牌发牌策略、机器人思考延迟均未改动。提示本身未改成异步算法。

- 新手牌到达时，客户端按帧预计算，不移动可见手牌；点击复用正在执行的任务或已完成结果。
- 冷点击立即显示“理牌中·取消”，不等待搜索结束。再次点击取消；已有缓存则直接理牌。
- 每个动画帧以 4 ms 为协作式计算预算；没有 requestAnimationFrame 的环境使用延后 16 ms 的定时回调。不通过 Promise 微任务连续计算来伪装分帧。
- 候选枚举、候选校验、排序、搜索和贪心兜底均有让出执行权的检查点。4 ms 是软预算，不是抢占式硬上限；单步规则判定、最终应用和 GC 仍可能超出预算。
- 完整结果仅应用一次，不显示会反复跳动的中间排法。原按钮的尺寸、位置、单行文本和缩字策略保持不变。
- 同手牌/级牌/规则/锁牌状态复用最多 8 条本地缓存；按局隔离，离桌清空。
- 出掉整组后保留剩余有效组合，不整手重算。拆掉组合、换手牌、换局、锁牌变化重新校验或取消；选牌、点同花顺、提示、出牌、托管/阶段阻断及离桌会取消待应用结果。
- 好友房关闭一键理牌时不预计算，也不开放按钮行为；进贡/还贡仍沿用现有可理牌权限。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| shared-core/src/arrangement/candidateSteps.ts | 直接枚举等价牌面组合，避免先展开重复的两副牌副本；规则仍以 getPlayInfo 为准 |
| shared-core/src/arrangement/resolver.ts | 单次规划内缓存同构牌型判定，保留同花信息并重绑红心配物理 ID |
| shared-core/src/arrangement/search.ts | 同一搜索策略的可暂停实现；位掩码减法、链式结果和分段稳定排序 |
| shared-core/src/arrangement/planner.ts | 同步调用与增量调用共享同一算法；离线参数跑分仍可复用 prepareHandArrangement |
| work/guandan-cocos/assets/scripts/game/HandArrangementJob.ts | 独立的帧调度、取消、缓存和耗时统计，不依赖 Cocos 场景或服务器 |
| HandWorkspace / TableHandInteractionController | 当前手牌事务、锁牌保护、过期结果失效、即时按钮反馈 |

实时 HandWorkspace 不再同步调用 HandGrouping.autoGroup。纯同步接口仍供非交互计算与测试使用。

另外在实际微信构建 JavaScript 中运行 26 手牌的冷点击流程：

- 点击入口 P95 1.19 ms，最大 1.44 ms；不含 Cocos 渲染、屏幕合成与触摸分发延迟。
- 单次分帧回调最大 14.23 ms（含最终结果应用）；每手最大回调耗时的 P95 为 11.00 ms。
- 缓存点击 P95 8.44 ms，最大 13.49 ms（含当前手牌再校验和应用）。

## 真机验收流程

需用新 `work/guandan-cocos/build/wechatgame` 包重新编译/预览；本轮未上传微信、推送 GitHub 或部署服务器。

| 操作 | 预期 |
| --- | --- |
| 经典、不洗牌各开一局，刚拿牌立即点一键理牌 | 立即反馈；未算完显示“理牌中·取消”；计时与操作不被长时间卡住 |
| 计算中再点按钮，或触摸选牌 | 取消待应用结果，不突然跳牌、丢选择 |
| 理牌完成后复原，再理牌 | 复用缓存，明显快于首次冷计算，牌面结果一致 |
| 锁定组合后理牌；出完整一组；再拆一组出牌 | 锁牌不拆；整组出牌不整手重算；拆组后剩余牌合法且无重复遗漏 |
| 进贡/还贡时理牌，然后完成交换 | 理牌可用；交换前的计算不会排回已经交换的牌 |
| 计算中开托管、切后台/恢复、换局或返回大厅 | 不应用过期结果；返回新牌局可正常重新理牌 |

交付时保留原素材与布局，仅新增忙碌/取消文字；遵循本轮 UI/UX 交互检查中的即时反馈、可取消和避免内容跳动要求。
