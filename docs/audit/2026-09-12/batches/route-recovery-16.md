## 覆盖与结论

| 模块 | 本批核验 |
| --- | --- |
| PageRouter | 页面重建先停用旧节点、递归停 Tween，再延迟销毁；同路由重建不重复发路由改变通知 |
| 匹配等待 | 请求代际、重复点击、轮询、等待 join 后取消、已分配席位恢复、取消状态不明时保留凭证 |
| 好友房 | busy/代际、迟到创建结果补偿、同房结果保护、已交接席位保护、同步入桌失败释放 |

| 启动 | 资源加载、96%初始化、场景就绪门禁、分阶段失败重试、部分初始化后显式重启 |
| 分享与DTO | 邀请信息与游戏票据分离、普通匹配恢复严格校验、错误反馈及等待状态 |

UI/UX 技能用于核对异步操作反馈、离开后不回写及重复操作边界；未做视觉重设计，也未把内存UI节点断言当作安全区或像素验收。

## 证据边界

- 无真实HTTP、外网请求、微信授权/邀请发送、用户数据、Cocos构建、引擎重启或线上部署。
- 路由探针让destroy保持isValid，以验证延迟销毁前先停用；不是真实引擎输入分发、GPU画面或触屏验收。
- 原lobby-entry回归的EventTarget.off为空。其成功不证明解绑有效；新增恢复探针使用可移除监听的替身，但也不覆盖全部真实页面所有者。
- 恢复网关补充探针仅普通match分支；好友房normalize函数、完整queue目录及实际HTTP client未被此探针覆盖。真实入桌契约辅助测试的签名/claims端口为合成，不作为鉴权安全证明。
- 启动测试的restart为存根；没有实际重启，也没有证明微信96%加载问题不再出现。
- 游戏入口、FrontPageController和若干调用者仅辅助追查，未因被引用或测试加载算作新增完整审阅。
- 总台账既有24项问题未在本批修复。

## 后续人工验收建议

| 操作 | 期望 |
| --- | --- |
| 连续点击创建好友房，创建期间返回，再次创建 | 不重复入桌；旧结果不清理当前有效席位 |
| 开始匹配后立即取消；弱网中取消失败后选择稍后处理 | 界面有确定反馈；不误报已取消，仍能恢复有效牌局 |
| 恢复牌局时切后台再回来 | 只进入当前有效席位，旧回调不覆盖当前页面 |
| 冷启动遇资源失败后重试 | 初始化前可重试；部分初始化失败不重复叠加初始化 |
| 分享卡进入、普通玩家/观战者恢复、退出再入 | 需实际微信和对应服务端端到端验收，不能由本批存根测试代替 |
